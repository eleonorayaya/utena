**Coder backend** (internal/coder/, internal/session/remotebackend.go): a session with `backend: coder` runs on a Coder workspace whose utena daemon runs with `--follower`. `session` defines `RemoteBackend` and keeps coder sessions free of local worktrees, session roots, mux records and the local reconcile/startup checks; `coder.Service` implements it and only `internal/api/app.go` wires it. Create, reactivate, archive and delete run in the background (the TUI client times out after 10s): create runs `coder create` (with `clone_dir` set to the follower session's directory, `/home/coder/utena-sessions/<ws>`, and `clone_branch` to the session branch or its base, so the template clones where the follower session will live and installs dependencies there; the follower workspace is linked at that clone, and a follower session whose worktree path is its workspace's own path adopts the checkout: the branch is checked out in place, `install_deps` is skipped, and delete removes neither the checkout nor the session root; the configured template must declare both parameters, or `coder create` fails; a repo whose name changes under `SanitizeSessionName` misses adoption and falls back to a worktree plus a full install), waits with `coder ssh <ws> -- true`, installs a workspace-scoped keepalive token over ssh stdin, adds the tuios host, opens the forward and creates the session on the follower, recording each stage as a setup step (`SetRemoteSteps`), followed by the follower's own setup steps, which the session detail pane shows in a Setup section while the session is creating or a step isn't done. The create request is stored on the session (`RemoteCreate`) until create finishes, so a daemon restart resumes it (`RemoteCreate.Resume`: an existing workspace skips `coder create`, the keepalive token is replaced, and a recorded follower session is reused); a coder session left `creating` by an interrupted reactivation goes back to `archived`; delete keeps the row as `deleted` until `coder delete` succeeds, and puts it back to `archived` with `status_error` on failure. While a forward is up the service polls the follower's `GET /sessions/{id}` every 3s and mirrors status, `status_error` and attention (`remote_attention_status`, returned by `Session.AttentionStatus()`) with targeted updates that never override archived, creating or deleted, and records the follower's branches as session branches against `remote_repo_id`, so PRs come from the leader's own PR sync. A follower creates no GitHub client and schedules no PR sync or PR activity jobs. A forward is held while the session is attached or an agent is working or needs attention, dropped after `idle_disconnect` otherwise, and restarted with backoff while held. Activation publishes `SessionActivated` with `Host`, `/mux/activations/next` returns it as `host` (omitted for local sessions), and `utena attach` runs `tuios attach --host <ws> <name>`; attach hooks carry `host` so they map to the coder session.
