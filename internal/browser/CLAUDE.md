**Browser** (internal/browser/, internal/webext/, internal/chrome/, internal/firefox/): `browser` owns the domain — `browser.Service` links sessions to browser windows, opens links in the session's window (deduping by URL prefix and focusing), and serves the `/browser` routes. It talks to browsers only through the `browser.Driver` interface. `internal/webext` is the production Driver, configured by `internal/chrome` or `internal/firefox` (only `internal/api/app.go` imports them; `--browser chrome|firefox|chrome-applescript`, env `UTENA_BROWSER`, default from `<configDir>/daemon.json` `{"browser": ...}` when the flag isn't given, else `chrome`); tests use `browser.FakeDriver`. One `background.js` serves both browsers: it uses `browser.*` when present, and picks its endpoint and hello `browser` name from its own origin scheme; the driver rejects a hello for another browser. Events are delivered on the `Subscribe` goroutine, never on the driver's read loop, because `Service.Open` holds its lock across driver calls. `internal/chromescript` is the extensionless Chrome driver (`chrome-applescript`): one bulk poll script (a handful of Apple events, so a Chrome quit can't be relaunched by a late event) returns windows, tabs, the active tab, window order and whether Chrome is frontmost; the focused window is window 1 while Chrome is frontmost. Chrome's PID (`pgrep`) is the run ID; `Subscribe` returns (so the service sees `Disconnected`) when a poll finds Chrome down or its PID changed, or after 3 failed polls in a row. A removed window is reported only after the next poll still finds Chrome running with the same PID, so windows closing during a quit aren't taken as closed by hand. Every script call has a 3s timeout, and actions never start Chrome (`CreateWindow` checks it's running first). `SessionsView.Warning` carries a driver's `WarningReporter` text to the TUI footer.

Window placement goes through a second seam, `wm.Driver` (internal/wm/). `internal/aerospace` is the production wm driver (only `internal/api` and `cmd/tui`, for the picker, import it); tests use `wm.FakeDriver`, and `wm.None` (`--wm none`) makes placement inert. `session.SessionService` publishes `session.attached` whenever the attached session changes; `browser.Module` subscribes and calls `Service.SetAttached`, which stores the ID atomically and signals a coalescing placement worker without taking the service lock. The worker links session-owned browser windows to wm windows (cached link, created-window diff, or a unique exact title; never by elimination, and ambiguous windows are left alone) and moves only misplaced ones: the attached session's windows to the browser workspace, every other owned window to the park workspace. Placement never focuses anything and never moves unowned windows. Focus is explicit: when `Open` focuses (attached or activated session, or a session-0 link), it calls `browser.Driver.FocusWindow` and then `wm.FocusWindow` on the window's linked wm window (resolved with the same rules; never guessed), because browsers can't reliably activate themselves and AeroSpace following native focus is not relied on. If no wm window is identified, `Open` logs a warning and still succeeds. `Open` never focuses a window on the park workspace: it places synchronously first when the session it focuses isn't the one placement last saw, and moves a wm window still on the park workspace to the browser workspace before focusing it. The daemon flags `--wm` (`aerospace`|`none`), `--browser-workspace` and `--park-workspace` (env `UTENA_WM`, `UTENA_BROWSER_WORKSPACE`, `UTENA_PARK_WORKSPACE`) live in `internal/api/config.go`. `OpenRequest.Attached` (`utena open --attached`, used by kitty's `open_url_with`) makes a request with no session ID open as the attached session (`Sessions.Attached`), or as a session-0 link when none is attached.

Window lifecycle: a `BrowserWindow` row records the `Driver` (`browser.Driver.Name()`: `chrome`, `firefox`, `chrome-applescript`) that owns it, and the `browser.Store` scopes every query to the daemon's driver, except lookups by row ID and `DeleteBySession` (every driver's rows); `BrowserState` (the run ID) is one row per driver; at start, rows and the run ID with no driver are claimed by the current one (`ClaimUnrecorded`). A row is `open`, `missing` or `snapshotted`, and keeps a rolling snapshot of its tabs (`Tabs`, `SnapshotAt`). `TabsChanged` schedules a snapshot at most once per ~2s; only `http(s)` tabs are saved, and an empty tab list never overwrites a saved one; the webext driver coalesces queued `tabs.changed` per window. `WindowRemoved` is held for a 2s grace: if `Disconnected` arrives first, the browser quit and the row becomes `missing` with its tabs (Firefox sends no `WindowRemoved` on quit; its open rows not live at the next `Connected` become `missing` there); if the grace expires, the user closed the window and the row is deleted; `Connected` also flushes pending removals to `missing`. Reattach runs only after a browser restart (a new run ID): unowned live windows are matched to `missing` rows by Jaccard overlap of normalized tab URLs (≥0.5, best first, ties left unmatched, each used once). The restore window (`Service.restoreWindow`) is 0 in production, so it is disabled: reattach happens only against the windows live at `Connected`, and `missing` rows are restored lazily right away. When set (tests only), a restart opens a restore window, which ends early once no `missing` rows remain (its end signals placement), for windows the browser restores late: an empty new window's adoption is deferred until it has URLs; windows rejected at `Connected` and daemon-created session-0 windows are never reattached; a late window with comparable URLs that matches nothing stays unowned. Session archive/delete arrive as `session.archived`/`session.deleted` (`SessionIDEvent`), which `browser.Module` puts on a non-blocking queue drained by a worker; a queued archive is skipped if the session is attached again. Archive clears the attached ID if it is that session, snapshots and closes its live windows (rows already pending removal are skipped, `missing` rows become `snapshotted`, a failed close reopens the row); delete closes its live windows and drops its rows. Both drop deferred adoptions into the session. While disconnected they only update rows, and the windows are closed on the next same-run `Connected`. Restore is lazy: placement restores the attached session when it has no live window, and `Open` restores a session with no live window; restored windows are created unfocused from their saved URLs (a row with no saved tabs is deleted instead), the active tab is reactivated (pinned state isn't), and during the restore window `missing` rows are skipped. A failed row is skipped, not fatal, and `Open` falls back to creating a window when nothing was restored. `Service.Eject` deletes an open row whose window is live (owned by the requesting session), cancels its snapshot and removal timers and wm link, and moves its wm window to the browser workspace when it is elsewhere; the window is then unowned and never re-adopted. `Service.MoveTab` moves a live tab (`Driver.MoveTab`, which keeps the page) into the target session's most recently focused live window and activates it there; with no live window it moves the tab into a new window (`Driver.DetachTab`) through `createSessionWindow`, which records the target's row and, like the blank and restored windows, goes through `createQuietly` inside `keepFocus`; an unrecorded window is closed only when it holds no web tabs. It never focuses and doesn't restore saved windows. The extension protocol is `3` (2 added `windows.remove` for `Driver.CloseWindow`; 3 adds `tabs.move` and `tabs.detach`, which uses `windows.create({tabId})`). The follower module doesn't forward `/eject` or `/move`.

Tab lifecycle: each saved tab is `pending`, `open` or `saved` (`TabState`). Only `pending` is stored (`SavedTab.State`); `open` and `saved` come from the window state (`SavedTab.StateIn`), because the bulk row updates never rewrite the tab JSON. Every write of a live window's tabs goes through `mergeTabs`: the live web tabs, plus every pending tab no live tab matches (`MatchTab`). An empty live list keeps the saved tabs. Reattach matching ignores pending tabs. A driver can report `Capabilities` (`CapabilityReporter`): `LoadTakesFocus` makes `Open` for a session that isn't attached (and isn't being activated) hold the link as a pending tab on the session's most recently focused open row, else its most recent restorable row, else a new `snapshotted` row with no driver window, without touching the browser and even while disconnected (`OpenResult.Pending`; a URL the row already has isn't added twice; a matching live tab in an open row is activated, which doesn't take focus, and a row whose window is the focused one gets the tab right away). `FocusChanged` on an owned window opens its pending tabs and clears their marks; a failed one stays pending. Restore loads pending tabs with the saved ones. Placement gives the attached session a window: when the attached session changes or the browser connects with a new run (`ensuredFor`), a session with no live window is restored, or gets a new window with no URLs; a window closed by hand isn't recreated until the next attach. `CreateTakesFocus` makes placement record the focused wm window (`wm.Driver.FocusedWindow`) before restoring or creating; right after each window is created, it waits for focus to move (up to `focusWait`) and focuses the recorded window again after `focusSettle`.
